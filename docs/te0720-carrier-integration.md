# TE0720 Carrier Integration — Power, Pins, Sequencing, Control

**Created:** 2026-06-18 · **Module:** Trenz TE0720-04-62I33MA (Zynq-7020, REV04, industrial)
**Sources:** TE0720 TRM v.108 (2025-10-14) + 4×5 SoM Integration Guide (2023-09-19), both Trenz public wiki. Cross-links: [`decoupling-audit.md`](decoupling-audit.md) §1, [`reset-strategy.md`](reset-strategy.md), [`pin-lock-todo.md`](pin-lock-todo.md), [`refdes-map.md`](refdes-map.md) §Sheet 2.

> Authoritative carrier-side requirements for the SoM (sheet 2). The module is a self-contained PoL system: it takes **two power inputs** and generates its own 1.0/1.5/1.8/3.3 V + DDR VTT. The carrier's job is clean power in, correct VCCIO bank voltages, correct control-pin pulls, and a compliant power-up order.

---

## 1. Module power rails (exact B2B pin map)

Pin numbers are **module-side (JMx)**. B2B is hermaphroditic — odd module pins mate to even carrier pins (JM1.1 ↔ JB1.2). "IN" = supplied by carrier; "OUT" = generated by module.

| Rail | Module pins | Dir | Rec. operating | Abs max | Schindler feed |
|---|---|---|---|---|---|
| **VIN** | JM1.1 / JM1.3 / JM1.5 / JM2.2 / JM2.4 / JM2.6 / JM2.8 (**7**) | IN | **3.15–5.25 V** | 6 V | **+5V** ✓ in-spec |
| **3.3VIN** | JM1.13 / JM1.15 (**2**) | IN | 3.15–3.45 V | 3.6 V | **+3V3** |
| **VCCIO35** (Bank 35 = VCCIOA) | JM1.9 / JM1.11 (**2**) | IN | 1.14–3.465 V | 3.6 V | **+3V3** |
| **VCCIO13** (Bank 13 = VCCIOD) | JM2.7 / JM2.9 (**2**) | IN | 1.14–3.465 V | 3.6 V | **+3V3** |
| **VCCIO34** (Bank 34 = VCCIOB) | JM2.1 / JM2.3 (**2**) | IN | **1.425**–3.465 V | 3.6 V | **+1V8_D** ⚠ boot |
| **VCCIO33** (Bank 33 = VCCIOC) | JM2.5 (**1**) | IN | 1.14–3.465 V | 3.6 V | **+1V8_D** |
| VBAT_IN | JM1.79 | IN | 2.5–5.0 V | 6 V | RTC backup (optional) |
| 3.3VIN / VREF_JTAG | JM2.91 | OUT | — | — | module sources JTAG VREF → JB2.92 |
| 3.3V | JM2.10 / JM2.12 | OUT | — | — | module 3.3 V out (unused on Schindler) |
| 1.8V | JM1.39 | OUT | — | — | module 1.8 V out (unused on Schindler) |
| 1.5V | JM2.19 | OUT | — | — | DDR (1.35 V on DDR3L variants) |

**Internal regulation (module page-20 schematic, REV04):** VIN → on-module bucks U1 MPM3840 (1.0 V core), U2 MPM3834 (1.5 V DDR), U3 MPM3834 (1.8 V); 3.3VIN → Q1 MP5077 load switch (3.3 V) + PG pull-ups + sequencing. U4 TPS51206 makes DDR VTT/VTTREF. Each on-module buck carries a 22 µF/10 V input cap (~66 µF total on VIN). The 10 V input-cap rating is itself the tell that VIN is designed for ~5 V.

## 2. Schindler rail → module mapping (the 7/6/3 split)

| Carrier rail | → module pins | Count |
|---|---|---|
| **+5V** | VIN (JM1.1/3/5 + JM2.2/4/6/8) | 7 |
| **+3V3** | 3.3VIN (JM1.13/15) + VCCIO35 (JM1.9/11) + VCCIO13 (JM2.7/9) | 6 |
| **+1V8_D** | VCCIO34 (JM2.1/3) + VCCIO33 (JM2.5) | 3 |

Schindler feeds **all** VCCIO banks from carrier rails (not from the module's M3.3VOUT / M1.8VOUT). Therefore **do not also tie the module's 3.3V (JM2.10/12) or 1.8V (JM1.39) outputs onto +3V3 / +1V8_D** — that would put two sources on one rail. The module outputs are left unused.

(Earlier docs estimated "+3V3 = 8 pins"; the TRM pin table supersedes that — it is **6**.)

## 3. VCCIO bank assignment (TE0720)

| Bank | VCCIO group | Schindler voltage | Used by |
|---|---|---|---|
| **B35** | VCCIOA | 3.3 V | HDMI-in (LT8619C U402) + ADV7280 (U500) |
| **B34** | VCCIOB | **1.8 V** | SDI (GS3470 U700 / GS2962 U701) — **boot-critical, see §4** |
| **B33** | VCCIOC | 1.8 V | Genlock ADC (AD9204 U801) |
| **B13** | VCCIOD | 3.3 V | HDMI-out (ADV7511 U403) + ADV7393 (U600) |

MIO banks (fixed, not carrier-set): **B501 = 1.8 V** (SDIO/eMMC/USB/ETH MIO), **B500 = 3.3 V** (QSPI/UART/I²C MIO). For 7-series Zynq, external buffers on MIO bank-1 pins (JB1 18/20/22/24/26/28) take their VCCIO from **JB1 pin 40 (1.8 V)** — relevant only if Schindler routes anything to those MIO pins.

## 4. ⚠ Boot-critical: VCCIO34 must be powered

Both sources are explicit: **VCCIO34 (Bank 34) must be connected to power even if the bank is unused** — it sets module start-up parameters. If unpowered, the **TE0720 will not boot and may not appear in the JTAG chain.** Min recommended **1.425 V** (the page-19 diagram shows the older 1.5 V floor; TRM v.108 is the newer value). *Mechanism (page-19 power diagram):* VCCIO34 is routed into an on-module **voltage detector (U23)** that gates the **System Controller's** power-good/sequencing logic — no VCCIO34 → the SC never completes its sequence → PGOOD never asserts → the SoC never releases from reset. That's the *why* behind the rule.

On Schindler, B34 = the SDI bank, fed from **+1V8_D**. So +1V8_D is doing double duty — SDI I/O *and* a boot-gate for the entire SoM. Consequence for power design: **+1V8_D must come up and stay up; it cannot be gated, load-switched, or sequenced-late behind anything.** Verify in the sequencing that U310 (the +1V8_D LDO) is enabled early and unconditionally.

## 5. Power-up sequence (TRM)

| Step | Event | Note |
|---|---|---|
| 1 | Config signals set + **VIN** + **3.3VIN** applied | control pins per §6 |
| 2 | **EN1** asserted (3.3 V ±5 %) | **do not assert before input power ≥ 90 % nominal** |
| 3 | Module internal rails (3.3 V / 1.8 V) reach nominal | SoM internal POR completes here |
| 4 | Carrier supplies **VCCIO35 / 34 / 33 / 13** | i.e. +3V3 + +1V8_D bank feeds |
| 5 | **PGOOD** goes high (3.3 V ±5 %) | all sources stable |

Practical read for Schindler: VIN (+5V) and 3.3VIN (+3V3) lead; **EN1 must be gated off until they're up** (ties into the LTC2954 soft-power / eFuse enable chain — confirm EN1 isn't asserted by a static pull-up that beats the input rails). The 3.3 V VCCIO banks ride +3V3 (same rail as 3.3VIN, so concurrent — fine). **PGOOD** is the SoM-ready flag for the PS/reset logic to watch.

## 6. Control / system-control signals (3.3 V — "do not leave floating")

The SoM's CPLD/supervisor control pins. TRM names first, Integration-Guide (SC_*) names in parens. **All are 3.3 V and must not float.** Pulls are placed on the carrier (sheet 2 or sheet 12 debug).

| Signal | Module.pin | Carrier.pin | Dir | Carrier pull | Function |
|---|---|---|---|---|---|
| **EN1** (SC_EN1) | JM1.28 | JB1.27 | IN | **pull-up** | Module power enable (can act as POR) |
| **NOSEQ** (SC_NOSEQ) | JM1.7 | JB1.8 | INOUT | **0 Ω → GND (recommended)** or pull-up | Selects power-mgmt mode — see note |
| **PGOOD** (SC_PGOOD) | JM1.30 | JB1.29 | INOUT | **pull-up** | Power-good (monitor only — **do not** use to enable bank voltages); also boot-mode on newer FW |
| **MODE** (SC_BOOTMODE) | JM1.32 | JB1.31 | IN | **pull-up** | Boot mode: low = SD, high = QSPI |
| **JTAGMODE** (JTAGSEL) | JM1.89 | JB1.90 | IN | **pull-down** | JTAG target: low = FPGA, high = CPLD |
| **RESIN** (SC_nRST) | JM2.18 | JB2.17 | IN | **pull-up** | Low-active module reset (forces SoC POR) |

**NOSEQ semantics (page-19 power diagram):** NOSEQ is OR-gated into the on-module rail enables (`EN_1V0 = NOSEQ | ON_1V0`, same for 1V8). **NOSEQ low (0 Ω → GND)** → the System Controller runs the managed power-up sequence (§5 order) — the right path for a Zynq. **NOSEQ high** → bypass: all rails enable together as soon as input power is present, no SC sequencing. **Recommend grounding via 0 Ω** unless there's a specific reason to bypass the module's sequencer.

**Reset-architecture interaction (see [`reset-strategy.md`](reset-strategy.md)):** RESIN/SC_nRST is the *module's own* power-on reset, and EN1 its power-enable — both sit **upstream** of the PS-driven `VIDEO_RESET_N` (3.3 V) and `SDI_RESET_N` (1.8 V) nets that release the on-carrier video chips. Boot order is: input power → EN1 → module POR (RESIN released) → PS boots → PS drives the two video-reset nets high to release the front-ends. PGOOD is the natural gate for "PS may proceed."

DIP switches are acceptable on MODE / NOSEQ / JTAGMODE per Trenz (bench flexibility), but the **default pull must still be present** so the pins never float.

## 7. Decoupling (carrier-side) — resolved

Module is robustly self-decoupled, so the carrier provides bulk reservoir + distributed HF only. Placed as **C200–C212 (13)** in the 2026-06-15 sweep; values confirmed here:

- **VIN / +5V** (7 pins): ~47 µF + 10 µF **≥16 V** X5R/X7R (derate for 5 V; 10 V is the strict floor but derates badly) + ~4× 0.1 µF distributed.
- **+3V3** (6 pins): ~22 µF + 10 µF (≥10 V) + ~4× 0.1 µF.
- **+1V8_D** (3 pins): 10 µF + one 0.1 µF per pin (3×).

At layout, spread the 0.1 µF to cover all **16** supply pins; keep the VIN bulk near the JM1/JM2 power entry. LSHM connector is rated **2.0 A/pin** (2 adjacent powered), so the 7-pin VIN carries the module's draw with wide margin.

## 8. Connectors & mechanical

- **B2B:** 2× Samtec REF-189016-02 (≈ LSHM-150-04.0-L-DV-A-S-K-TR, 100-pin) for JM1/JM2 + 1× REF-189017-02 (≈ LSHM-130, 60-pin) for JM3. Standard **8 mm** mating height (same connector both sides). Current 2.0 A/pin. Module dim **50 × 40 mm**.
- **Hermaphroditic / mirrored:** JB1.1 mates to JM1.2, etc. The KiCad carrier symbol must reflect the mirrored numbering.
- **Mounting:** 4 holes, **3.2 mm** dia, at the corners of a **34 × 44 mm** rectangle (also conduct module heat into the carrier). Place no high-dissipation parts under the module (no airflow). Verify B2B placement/rotation precisely before fab.

## 10. Carrier checklist (from the Integration Guide)

**Schematic:**
1. B2B pin numbers mirrored vs module (pin1↔pin2). ✓ in symbol
2. Connectors named JB1/JB2/JB3 (convention).
3. All GND pins on one common net.
4. **All VIN (PWR_1) pins tied together** (all 7).
5. JB2.92 = JTAG VREF (3.3 V, sourced from module JM2.91).
6. MIO bank-1 external buffers (if any on JB1 18–28) powered from **JB1.40 (1.8 V)**.
7. **§6 control pins all have their pulls; none float; VCCIO34 powered.** ← highest-stakes

**PCB:**
1. 4 mounting holes, 3.2 mm, 34×44 mm rectangle corners.
2. B2B headers placed/aligned precisely and locked; rotation checked (odd/even swap).
3. Height clearance below module obeyed; no hot parts underneath.

## 11. Verification findings + open items

**Netlist check 2026-06-18** (`SchindlerCarrierBoard_V1-wWires.net`; J200 = JM1, J201 = JM2, carrier symbol uses **direct module pin numbering**, not the JB mirror):

**✓ Power & VCCIO — correct and complete.** All 7 VIN pins (J200.1/3/5 + J201.2/4/6/8) → +5V; 3.3VIN (J200.13/15) + VCCIO35/B35 (J200.9/11) + VCCIO13/B13 (J201.7/9) → +3V3; VCCIO34/B34 (J201.1/3) + VCCIO33/B33 (J201.5) → +1V8_D — **boot-critical VCCIO34 IS powered**. VREF_JTAG (J201.91) → +3V3. Module outputs (1.8V J200.39, 3.3V J201.10/12) + VBAT (J200.79) correctly unconnected. No double-drive. C200–C212 sit on correctly-assigned rails.

**⚠ Control pins — DEFECT (the flagged gap, confirmed): 5 floating + 1 mis-tied.**

| Pin | Carrier net | Status | Fix |
|---|---|---|---|
| EN1 (J200.28) | unconnected | **FLOATING** — enable undefined | pull-up 10k → +3V3 (or PG-gated) |
| NOSEQ (J200.7) | **+3V3 (hard tie)** | sequencer **bypassed** | resistor → **GND** to use CPLD sequence |
| PGOOD (J200.30) | unconnected | **FLOATING** | pull-up 10k → +3V3 (+ PS GPIO/LED) |
| MODE (J200.32) | unconnected | **FLOATING** — boot mode random | pull per boot src, or wire to SW1200 |
| JTAGMODE (J200.89) | unconnected | **FLOATING** | pull-down 10k → GND (FPGA) |
| RESIN (J201.18) | unconnected | **FLOATING** — reset undefined | pull-up 10k → +3V3 (or to SW1201) |

None are wired on sheet 12 either (unconnected board-wide).

**Decisions — RESOLVED 2026-06-18 (Claude's calls, Justin delegated):**

| Pin | Decision | Part |
|---|---|---|
| EN1 | pull-up 10k → +3V3 **+ 1 µF → GND** (~10 ms RC delay, lags rails) | R213 + C213 |
| NOSEQ | **0 Ω → GND** (use CPLD sequencer; remove the current hard +3V3 tie) | R214 |
| PGOOD | pull-up 10k → +3V3, route to a PS GPIO (reset gate) + opt. LED | R215 |
| MODE | pull-up 10k → +3V3 (**QSPI default**) + net `BOOT_MODE_SEL` → SW1200 (DIP→GND = SD) | R216 |
| JTAGMODE | pull-down 10k → GND (FPGA) | R217 |
| RESIN | pull-up 10k → +3V3 + net `SOM_RESET_N` → SW1201 (momentary→GND) | R218 |

*MODE assumes QSPI-primary boot (FSBL/u-boot in QSPI, rootfs on eMMC), SD as dev/recovery. EN1 RC is tunable; upgrade to a PG-gate only if bring-up shows a sequencing issue.* Cross-sheet nets `BOOT_MODE_SEL` / `SOM_RESET_N` connect the previously-stranded SW1200/SW1201.

**Implementation verified 2026-06-18** (Claude, coordinate + ERC check on `02-te0720-som-backbone.kicad_sch`): agent placed R213–R218 + C213; all six straps land on the correct control nets and rails (EN1→+3V3 + C213→GND; NOSEQ→GND, old +3V3 tie removed; PGOOD→+3V3; MODE→+3V3; JTAGMODE→GND; RESIN→+3V3), BOOT_MODE_SEL→SW1200 + SOM_RESET_N→SW1201 wired. ERC cleared the 5 floating pins (pnc 252→247). **⚠ On-disk netlist exports (`-wWires.net`, `a.net`) are STALE — they don't contain R213–R218; regenerate the netlist of record before any PCB “Update from Schematic” / build.**
